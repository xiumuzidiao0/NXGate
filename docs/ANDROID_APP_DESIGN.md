## 一、 产品定位与核心设计哲学

### 1. 定位：纯远程运维管控中心 (Pure Remote Management Console)
- **不做本地 VPN 数据转发**：不调用 Android `VpnService`，不挂载移动端 TUN 虚拟网卡，完全杜绝移动端常驻后台导致的耗电、断网保活与系统权限封锁问题。
- **专精多服务器集群运维**：将散落在不同云服务商（阿里云、甲骨文、搬瓦工、AWS等）的 Linux VPS 统一收纳，随时在手机端查看出口健康度、监控实时网速、一键触发住宅节点轮换。

### 2. 视觉设计系统 (Design Tokens)
与 Web 控制台的深空体系（Deep Space Theme）高度一致：
- **基底色阶**：
  - 背景色：`#0a0e15` (Deep Space Dark)
  - 卡片一级表面：`#121824` (`Surface-1`)
  - 卡片二级表面 / 输入框：`#1a2234` (`Surface-2`)
  - 边框线色：`rgba(255, 255, 255, 0.08)`
- **功能强调色**：
  - 品牌强调蓝：`#4dcadc` (Cyan Pulse)
  - 成功/已连通：`#10b981` (Emerald Green)
  - 警告/注意：`#f59e0b` (Amber)
  - 故障/阻断：`#ef4444` (Crimson Red)
- **动效手感**：
  - 采用 Material 3 阻尼弹簧动效（Spring Damping: 0.82），卡片展开收起丝滑轻盈。

## 二、 全局交互核心：跨页面多服务器秒级切换机制

### 1. 业务痛点
传统管理 App 在进入“隧道列表”或“多端口规则”后，如果要切换到另一台 VPS，往往需要退回首页、重新点击进入对应服务器，在多机运维场景下交互成本极高。

### 2. 架构设计：`GlobalServerSwitcher` 顶栏挂载

在 **Tab 2 (监控)**、**Tab 3 (调度)**、**Tab 4 (节点)**、**Tab 5 (系统)** 的顶部 `TopAppBar` 均强制吸顶嵌入 **服务器选择器胶囊**：

```
┌─────────────────────────────────────────────────────────┐
│ 导航栏:         [ 🇯🇵 东京住宅网关 ▾ ]             [ 🔄 刷新 ] │
└─────────────────────────────────────────────────────────┘
```

#### 交互行为
1. **点击顶栏胶囊**：屏幕底部平滑升起 `ServerSwitcherBottomSheet`，展示所有已保存的 VPS 列表；
2. **列表卡片信息**：
   - 国家国旗 Emoji、服务器别名、公网 IP:Port；
   - 秒级心跳指示灯（绿点/黄点/红点）与 Ping 延迟（如 `42ms`）；
   - 当前正在使用的物理出口 IP 及 AI 解锁徽标；
3. **点选切换**：
   - 单击任意目标 VPS，底部弹窗收起；
   - **当前所在页面数据就地刷新**：通过全局 `ServerRepository.activeServerId: StateFlow<String>` 广播事件，无需离开当前页面，直接拉取新 VPS 的监控图表或分流规则；
4. **手势快切**：在顶部标题栏区域左右水平轻扫（Swipe Horizontal），可按照列表顺序快速切至上一台/下一台服务器。

### 3. Tab 3: 调度中心与边缘入站 (Routing Matrix & Ingress)

> **核心使命**：管控该 VPS 的“多端口代理分流规则”、“动态自适应组”与“sing-box 抗审查协议”。

#### 顶部分段选择器 (Segmented Button)
- `[ 🔀 多端口分流 ]`
- `[ 🤖 动态自适应组 ]`
- `[ 🛡️ 边缘抗封锁入站 ]`

#### 分页 1：多端口分流 (Multi-Port Matrix)
- **端口规则卡片**：
  - 展示端口号（如 `PORT 7928`、`7929`、`7930`）及开启状态 Switch 开关；
  - **调度策略徽章**：`轮询 (Round-Robin)`、`随机 (Random)`、`定时轮换 (Interval 300s)`；
  - **鉴权模式标签**：
    - `免密直连 (none)`：绿色标签；
    - `系统随机账密 (random)`：青色标签，显示绑定的独立用户名（如 `vpn_22zqhi`），点击旁边眼球图标可查看密码；
    - `自定义账密 (custom)`：紫色标签；
  - **绑定范围**：显示“绑定全部健康隧道”或“绑定 2 个动态自适应组”；
- **新建/编辑端口弹窗 (Floating Drawer)**：
  - 输入监听端口号；
  - 策略选择（单选卡片）；
  - 鉴权设置：支持一键点击 `🎲 随机生成账密` 自动填充高强度字母数字密码。

#### 分页 2：动态自适应组 (Dynamic Groups)
- **系统核心组 (`system-primary`) 卡片**：
  - 显示系统主出口守护参数，锁定设备为 `tun0`，显示目标维持数（固定 1 个）。
- **自定义自适应组卡片**（如“日本Top3住宅组”）：
  - 国家目标：`JP`；网络类型：`Residential`；解锁要求：`AI 全解`；
  - 维持数量：`3 个并发`；重新评估周期：`15 分钟`；
  - 当前维持的隧道列表展示；
  - 按钮：`⚡ 立即重评换线`（重新触发探测选优）。

#### 分页 3：边缘抗封锁入站 (sing-box Ingress)
- **协议入站列表**：
  - 展示正在运行的入站节点：`VLESS-REALITY`、`Hysteria2`、`TUIC`、`Shadowsocks`；
  - 关键参数：外部端口、UUID / Password、SNI / Host；
  - **当前出口指向**：显示 `链式出口 ➜ [PORT 7928 日本住宅池]` 或 `[VPS 本地直连]`；
- **操作面板**：
  - `📱 节点二维码`：弹出专属分享二维码，供客户端相机扫码；
  - `🔄 更改出口`：轻点直接将该 REALITY 节点的出口无缝改挂到 7929 或其他自适应端口。

### 5. Tab 5: 系统运维与网关管理 (Server System & Maintenance)

> **核心使命**：服务端核心全生命周期管理，集成**版本检测与在 App 内一键热升级**、**age 端到端前向安全加密策略配置与密钥生成**、**免密 SubToken 令牌隔离**、**Telegram 告警通道测试**与**网关自愈工具箱**。

#### UI 布局与功能模块
1. **服务端版本与自愈更新 (`ServerUpdateCard`)**：
   - 实时读取远端网关运行版本（如 `v2.5.9`）与目标架构；
   - 点击「检查更新」：调用 `GET /api/update/check` 探测 GitHub Releases 最新发行包；
   - 发现新版本时展示版本号、发布日期与日志详情；
   - 点击「升级服务器」：调用 `POST /api/update/trigger`，启动带进度的轮询状态监听（`GET /api/update/status`），在界面实时展示下载、SHA-256 校验与 systemd 服务平滑重启自愈阶段；
2. **age 端到端前向安全加密 (`AgeSecurityCard`)**：
   - 开关控制：开启/停用 age 订阅安全加密；
   - Recipient 公钥输入与展示（支持 `age1...` 及后量子 `age1pq...` 规范）；
   - 内置「生成新密钥对」工具：支持 `X25519` 与 `MLKEM768-X25519` 混合抗量子算法，生成后一键复制私钥并一键应用公钥；
   - 内置「从私钥推导公钥」工具：输入已有私钥自动推导对应公钥并填入；
   - 点击保存持久化至服务端的 `/api/settings`；
3. **免密订阅令牌管理 (`SubTokenCard`)**：
   - 展示当前 16 位安全令牌，防范直接扫描管理后台路径；

## 四、 通信契约与二维码导入标准 (Protocol Specification)

### 1. 二维码与 URI 导入规范 (`nxgate://server`)

App 相机扫描 Web 控制台弹窗二维码，解析到的标准统一协议格式：

```text
nxgate://server?host=<HOST>&port=<PORT>&path=<PATH>&user=<USERNAME>&pass=<PASSWORD>&name=<ALIAS>&tls=<0|1>
```
*(同时向下兼容解析历史 `aimili://server` 格式)*

#### 字段定义表
| 参数名 | 类型 | 说明 | 示例 |
| :--- | :--- | :--- | :--- |
| `host` | String | VPS 公网 IPv4 / IPv6 地址或解析域名 | `47.238.2.197` |
| `port` | Int | Web 控制台开放的端口 | `8787` |
| `path` | String | 后台安全访问路径 (Secret Path) | `enter` |
| `user` | String | Web 管理员账号 | `xmzd` |
| `pass` | String | Web 管理员明文密码 (URL 编码) | `a18979346882` |
| `name` | String | 显示给用户的节点备注别名 (URL 编码) | `NXGate+(47.238.2.197)` |
| `tls` | Int | 是否通过 TLS (HTTPS) 协议通信 (0=HTTP, 1=HTTPS) | `0` |

### 2. 标准 JSON 导入格式 (用于剪贴板备份与导入)
```json
{
  "type": "nxgate_server",
  "version": 1,
  "name": "东京住宅网关",
  "host": "47.238.2.197",
  "port": 8787,
  "path": "enter",
  "username": "xmzd",
  "password": "your_password",
  "proxy_port": 7928,
  "tls": false
}
```
*(系统导入时向下兼容历史 `aimili_server` 类型对象)*

### 3. API 鉴权与端点映射矩阵 (v2.5.9)

App 所有网络请求必须带上以下 Header 之一完成鉴权：
- **方案 A (推荐)**：`Authorization: Basic <Base64(username:password)>`
- **方案 B (SSE 长连接回退)**：在 URL 后追加参数 `?user=<username>&pass=<password>`

| 模块 | 请求方式与路径 | 功能作用 |
| :--- | :--- | :--- |
| **App 握手** | `GET /api/app/info` | 秒级测活、获取版本号、在线物理出口、网速与系统能力集 |
| **配置导出** | `GET /api/app/profile` | 获取当前服务器完整导出对象与 `aimili://` 链接 |
| **运行概览** | `GET /api/status` | 获取完整的 VPN 状态、总流量快照、动态组和端口总览 |
| **实时推流** | `GET /api/events` (SSE) | 监听实时流量滑动窗口数据波形推流与系统运维事件广播 |
| **节点广场** | `GET /api/nodes` | 获取清洗后的候选节点（含住宅标签、三大 AI 解锁与评分） |
| **节点测速** | `POST /api/nodes/probe` | 触发服务器对指定节点进行并发端口预检与延迟测速 |
| **节点加星** | `POST /api/nodes/favorite` | 收藏 / 取消收藏特定节点 |
| **隧道矩阵** | `GET /api/tunnels` | 罗列所有物理并发隧道网卡（`tun0`, `tun1`...）详情 |
| **隧道启停** | `POST /api/tunnels/start` | 为指定节点建立新隧道并自动分配策略路由表 |
| **隧道销毁** | `POST /api/tunnels/stop` | 销毁指定隧道，回收虚拟设备并清理策略路由 |
| **自适应组** | `GET /api/tunnel-groups` | 获取自适应池列表、当前维持隧道与筛选策略 |
| **⚡ 一键换线**| `POST /api/tunnel-groups/evaluate` | 立即触发重评，淘汰假死节点，秒级换上最优住宅出口 |
| **多端口分流**| `GET /api/proxy/ports` | 获取多端口监听器列表、绑定关系与随机凭据鉴权模式 |
| **端口规则应用**| `POST /api/proxy/ports` | 下发修改端口规则（添加新端口、调整轮询策略或账密模式） |
| **边缘入站** | `GET /api/singbox/nodes` | 获取 sing-box 托管的 REALITY、Hy2、TUIC、SS 等节点列表 |
| **更改出口** | `POST /api/singbox/nodes/outbound` | 动态挂载某个入站协议的链式出口到指定代理端口 |
| **Clash 订阅** | `GET /api/singbox/subscription/clash` | 获取标准化 Clash Meta / Mihomo 分流订阅 YAML 文件 |
| **屏蔽库复活** | `POST /api/blacklist/resurrect` | 对黑名单中被熔断的隔离节点执行自动探活与解封复活 |

## 五、 Android 技术选型与推荐工程目录

### 1. 技术栈实践 (Production Implementation)
- **语言**：Kotlin 2.0+ (100%)
- **UI 框架**：Jetpack Compose (Material 3) + Navigation Compose + Edge-to-Edge
- **异步与数据流**：Kotlin Coroutines + `StateFlow`
- **网络与推流通信**：OkHttp 4.12+ (内置 EventSource `okhttp-sse` 实现 `/api/events` 长连接)
- **本地安全存储**：Android KeyStore 硬件保护的 `EncryptedSharedPreferences` (`androidx.security:security-crypto:1.1.0-alpha06`, `AES256_SIV` + `AES256_GCM`)，支持旧版本明文无感自动迁移
- **系统级深度集成**：
  - **下拉快捷设置磁贴 (`NXGateTileService`)**：原生 Android `TileService`，通知栏动态展示网关在线状态与延迟，一键后台换线；
  - **桌面小部件 (`NXGateWidgetProvider`)**：原生 Android AppWidget 桌面微件，常驻显示当前活跃服务器、物理出口 IP、实时上下行网速，并支持在桌面一键换线与刷新；
  - **外部代理客户端一键直连导入 (Deep Link)**：在订阅面板中支持通过 `clash://`、`sing-box://`、`v2rayng://` 原生 URI 协议一键唤起外部代理客户端静默导入，未安装时自动安全回退复制；
  - **韧性 SSE 与微状态胶囊**：长连接断开时带抖动指数退避自动重试（1s..16s），并在顶层呈现优雅的无表情包状态指示微胶囊；
  - **节点广场热力色阶与多维排序**：极速/良好/一般/偏高 4 级色阶状态点，支持延迟优先、带宽优先、稳定度优先多维排序；
  - **本地断流与故障转移推送通知 (`NotificationHelper`)**：Android 13+ `POST_NOTIFICATIONS` 运行时权限与双渠道通知（`nxgate_alerts` / `nxgate_status`）；
  - **生物识别加固**：BiometricPrompt（指纹/面容/凭据），加入 60 秒切后台免重复弹锁宽限期，屏幕旋转不重复打扰；
  - **交互触感反馈**：全场景接入系统级 `LocalHapticFeedback`；
  - **节点广场性能优化**：200ms 搜索输入防抖，千量级长列表过滤计算移入 `Dispatchers.Default` 避免掉帧；
  - **集群配置管理**：全量网关配置标准 JSON 导出、剪贴板复制、系统分享与合并导入。
